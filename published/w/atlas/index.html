Atlas

La carte n’est pas un export de vos données : c’en est une vue. Dans Grist, couches, symbolisation, relief et récit vivent avec vos tables — quand la donnée change, la carte a déjà changé. Hors document, la même scène peut aussi s’ouvrir seule à partir d’un manifeste publié.

Dans Grist, on partage le document : la carte suit, avec les droits du document. On peut aussi publier une scène seule (manifeste) pour l’ouvrir hors document — même moteur, autre hôte.

Construire, diffuser, relever

Construire, dans votre document

Atlas est un widget de votre document, à côté de vos tables. Ce que vous modifiez sur la carte est écrit dans la table, et l’inverse. Les règles d’accès du document s’appliquent telles quelles : qui peut écrire édite, qui ne peut que lire voit la scène et le récit, sans que l’édition lui soit proposée.

Il n’y a pas de droits Atlas à configurer en plus de ceux de Grist. C’est le document qui décide, y compris au niveau d’une table ou d’une ligne — et c’est aussi là que la persistance se voit : tables système, couches, récit.

Diffuser, proprement

Deux paramètres Grist, deux intentions. `?embed=true` : page minimale en lecture forcée. `?style=singlePage` : même contour minimal, mais les droits de la personne connectée s’appliquent (un éditeur reste éditeur). Pour un public sans compte, activez Public Access (Viewer) et, si besoin, des Access Rules ou des link keys — sinon le lien demande une connexion.

Ce n’est pas une publication Atlas à part : c’est le document (ou une scène publiée via `?scene=`). Retirer l’accès ou le manifeste suffit ; rien n’a été recopié ailleurs. L’iframe de diffusion doit montrer la carte, pas le chantier des tables.

Relever sur le terrain

Une application Android ouvre les scènes de votre compte sans passer par un document dans le navigateur. Ce n’est pas une interface différente pour le plaisir : c’est le seul moyen d’être authentifié hors du moteur web, celui-ci ne pouvant pas présenter de clé API à l’instance.

La démonstration : une scène réelle

Le ruisseau des Aygalades, au nord de Marseille, busé sur une grande partie de son cours et franchi par l’autoroute. Sept couches OpenStreetMap, huit étapes de récit, deux sortes de 3D : les modèles du catalogue posés sur du mobilier relevé, et un relevé photogrammétrique de la cascade elle-même.

Aucun document Grist : la scène est un fichier publié, ouvert par son adresse. Données © les contributeurs OpenStreetMap (ODbL) ; relevé 3D de M.Dailly (CC BY 4.0).

Ce qu’il fait

  • Vos tables deviennent des couches — toute table portant une géométrie est reconnue et posée sur la carte, avec ses attributs.
  • Symbolisation par la donnée — couleur par catégorie ou graduée, étiquettes, extrusion. La règle est enregistrée dans le document et suit la scène.
  • Relief et volumes — modèles 3D posés sur le terrain réel, ombres portées à l’heure choisie, surfaces extrudées calées sur l’altitude.
  • Un récit qui se rejoue — chaque étape retient le cadrage, les couches visibles, les filtres et l’heure — et reste juste quand la donnée change.
  • Les droits du document font foi — aucune liste d’accès propre à Atlas : en lecture seule l’édition disparaît, le récit reste consultable. ACL et link keys Grist s’appliquent tels quels.

Le parcours

  1. Je charge mes données

    Une table du document, un GeoJSON, OpenStreetMap, un projet QGIS via qgis2grist — ou une couche publiée par URL dans un Scene Manifest.

  2. J’édite

    Attributs, géométries, volumes 3D. Ce que je modifie sur la carte est écrit dans la table : c’est la même donnée, pas une copie.

  3. Je compose mon récit

    Chaque étape retient le cadrage, les couches visibles, les filtres et l’heure. Le récit se rejoue, et il reste juste quand la donnée évolue.

  4. Je règle les accès dans Grist

    Atlas n’a pas son propre système de droits. Public Access, ACL et link keys du document décident qui voit quoi — y compris dans une iframe.

  5. Je partage

    Soit le lien d’une page du document (`embed` ou `singlePage`), soit une scène publiée ouverte avec Atlas seul (`?scene=`). Dans les deux cas, rien n’est recopié vers une autre plateforme carto.

Sur le terrain, sans navigateur

Une application Android ouvre vos scènes depuis votre compte Grist. Elle existe parce qu'un navigateur ne peut pas présenter de clé API à l'instance : celle-ci refuse l'en-tête d'authentification au contrôle préalable, et cela ne se change pas côté serveur. L'application émet ses requêtes hors du moteur web, ce qui lève l'obstacle.
